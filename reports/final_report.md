# Отчёт по лабораторной работе №12
## Коллективная работа над исследованием

**Проект:** Game of Thrones — Interactive Dashboard  
**Репозиторий:** https://github.com/truk808/-11

## 1. Цель работы
Освоить инструменты коллективной работы над исследовательским проектом с использованием GitHub: Issues, Projects, ветвления, Pull Requests, Code Review, Wiki и документации.

## 2. Исходное состояние репозитория
В репозитории ЛР11 присутствуют README.md, LICENSE (MIT), .gitignore и HTML-файл интерактивного дашборда. Проект предназначен для анализа смертей персонажей и сражений по CSV-данным.

## 3. Организация совместной работы
Для ведения задач предлагаются GitHub Issues с направлениями:
- сбор и проверка исходных CSV-данных;
- анализ данных и визуализации;
- документирование методологии, результатов и выводов.

Для отслеживания состояния задач используется GitHub Projects с колонками **To Do**, **In Progress**, **Review**, **Done**.

## 4. Правила участия
В корень репозитория добавлен файл `CONTRIBUTING.md`. В нём описаны создание Issue и feature-веток, требования к коммитам и Pull Request, порядок Code Review и базовая проверка проекта.

## 5. Ветвление и Pull Requests
Для выполнения независимых задач предусмотрены ветки:
- `feature/data-collection`;
- `feature/analysis`;
- `feature/documentation`.

Рабочий процесс: создание ветки от `main` → коммиты → Pull Request → проверка изменений → исправления → merge после одобрения.

**Фактические номера веток, PR, комментарии Code Review и даты необходимо указать после выполнения этих действий в GitHub.** Они не фиксируются заранее, чтобы не выдавать запланированные действия за выполненные.

## 6. Документирование исследования
Для GitHub Wiki подготовлены рекомендуемые страницы:
- Введение;
- Методология;
- Результаты;
- Выводы;
- Список литературы.

Содержание страниц должно соответствовать фактически использованным наборам данных и результатам анализа.

## 7. Организация данных
Предлагаемая структура:
- `data/raw` — исходные CSV;
- `data/processed` — подготовленные данные;
- `notebooks` — исследовательские ноутбуки (если используются);
- `scripts` — скрипты обработки;
- `results` — промежуточные результаты;
- `reports` — отчёты.

В текущем HTML данные загружаются пользователем в браузер; CSV-файлы не являются частью исходного репозитория. Перед добавлением больших файлов следует оценить необходимость Git LFS и права на распространение.

## 8. Внешние инструменты и автоматизация
Дополнительно могут применяться Zotero для библиографии и Overleaf/Google Docs для совместного написания текста. GitHub Actions можно подключить для автоматической проверки файлов. Эти возможности следует отмечать как выполненные только после фактической настройки.

## 9. Анализ эффективности совместной работы
GitHub Issues помогает фиксировать задачи и их критерии готовности; Projects показывает статус выполнения; ветки позволяют вести независимую разработку; Pull Requests обеспечивают обсуждение и проверку изменений до включения в основную ветку. Для оценки эффективности после совместной работы следует сопоставить количество закрытых задач, длительность их выполнения, замечания Code Review и число исправлений.

## 10. Заключение
В рамках ЛР12 подготовлена документационная основа для коллективной работы над исследовательским дашбордом: правила участия, шаблоны задач и Pull Request, структура отчёта и рекомендации по организации веток, проекта и Wiki. Для завершения практической части необходимо создать Issues, Project, ветки и Pull Requests непосредственно в GitHub, провести Code Review и заполнить отчёт фактическими ссылками и результатами.
